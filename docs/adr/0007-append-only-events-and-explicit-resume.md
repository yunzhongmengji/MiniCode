# ADR-0007：使用追加事件、独立 Artifact 与显式 Checkpoint 恢复

状态：Accepted
日期：2026-09-09

## 背景

M5 已经能够通过 Policy、Approval 和受限工具执行模型动作，但一次任务结束后只能从返回值和临时测试输出推测过程。模型调用、策略判断、工具执行、取消和超时没有统一时序；大工具输出若直接写入事件会使日志无限增长；发生部分失败时，也无法区分哪些工具已经完成、哪些仍需要执行。

M6 需要同时解决四个不同问题：

1. 以 Provider 无关格式记录运行事实。
2. 保存工具输出而不把正文塞入每个事件。
3. 在部分工具已经完成后提供安全恢复点。
4. 只读解释历史，而不在审计过程中再次产生副作用。

## 决策

1. 使用 `LedgerEvent(run_id, sequence, kind, payload)` 表示一项不可变事实，单次运行中的 sequence 从 1 连续递增。
2. QueryLoop 与 ToolDispatcher 共享同一个 EventLedger，分别记录运行、模型、策略、审批、工具、checkpoint 和最终状态事件。
3. Event payload 只接受递归 JSON 兼容值，并在事件构造时生成不可变快照；默认不记录 Prompt、模型正文、工具参数全文或 API 凭据。
4. 工具成功输出和预期失败文本可写入 ArtifactStore，事件只保存内容寻址引用、媒体类型和 byte 数。
5. 每个 ToolResult 加入对话历史后立即保存 RunCheckpoint，而不是等待整批工具全部完成。
6. RunCheckpoint 强制 ToolCall ID 唯一、ToolResult 与更早的调用匹配、每个调用最多一个结果，并校验已用工具计数。
7. `QueryLoop.resume()` 只补执行没有 ToolResult 的 pending 调用，延续原有回合与工具预算，再进入下一模型回合。
8. `run()` 与 `resume()` 使用同一总超时和结束事件边界，取消、超时与普通失败继续向调用者传播。
9. RunReplay 只读取并验证事件，生成运行摘要；Replay 不调用模型、不执行工具，也不承担恢复职责。
10. 第一版提供内存实现以验证协议与状态语义，持久 Event/Artifact/Checkpoint 后端留给后续实现。

## 正面后果

1. 模型、工具、策略和运行级结果进入同一条连续时序，可以从事件解释一次任务的执行路径。
2. 指标、审计和恢复不再依赖 Provider SDK 对象或非结构化日志文本。
3. 大工具输出与轻量事件分离，事件仍可通过 Artifact 引用定位原始内容。
4. 每个已完成 ToolResult 都形成恢复点，多工具批次中后一个失败时不会必然重跑前一个工具。
5. 事件记录不吞掉异常或取消，观察能力不会改变现有控制流。
6. Replay 与 Resume 明确分离，查看历史不会产生新副作用。
7. EventLedger、ArtifactStore 和 CheckpointStore 都以 Protocol 作为替换边界，后续可加入持久实现而不修改 QueryLoop 主协议。

## 负面后果

1. 同一业务动作会产生多个事件，测试和文档必须维护稳定顺序与 payload 约定。
2. EventKind 稳定值与 payload 字段成为兼容性接口，未来修改需要版本化或迁移。
3. 每个工具结果保存 checkpoint 会增加持久后端的写入次数。
4. 事件、Artifact 和 Checkpoint 分开保存后，持久实现需要处理跨存储一致性。
5. 仅凭 checkpoint 不能确定崩溃发生前外部副作用是否已经完成但结果尚未保存，非幂等工具仍可能存在重复执行风险。
6. 当前内存实现不能跨进程恢复，也不提供多线程或多进程并发保证。
7. 当前 RunReplay 只做基础结构验证，不是完整的事件状态机或确定性程序重演器。

## 备选方案

1. 只使用普通日志字符串。
   - 实现简单，但无法稳定验证字段、顺序、关联 ID 或自动生成回放摘要，因此不采用。

2. 在一个对象中同时保存事件、完整输出和最新状态。
   - 读取方便，但审计事实、大内容和可恢复状态具有不同生命周期，会导致对象膨胀和职责混乱，因此拆分存储。

3. 只在整批工具全部成功后保存 checkpoint。
   - 写入次数较少，但中途失败会丢失已经完成的工具结果，恢复时可能重复副作用，因此按每个 ToolResult 保存。

4. Replay 时重新执行模型和工具。
   - 无法保证非确定性模型输出一致，还可能重复文件写入或进程副作用，因此 Replay 保持只读。

5. 捕获异常后返回统一失败 RunResult。
   - 会隐藏原始异常类型和取消语义，当前选择先记录事件再原样抛出。

## 重新评估条件

1. CLI 或服务需要跨进程恢复时，引入 JSONL、SQLite 或数据库实现，并定义提交与崩溃一致性。
2. 事件格式需要长期兼容或跨版本读取时，引入 schema version 与迁移策略。
3. Artifact 可能包含秘密或多人共享时，引入加密、访问控制、脱敏、保留期限和垃圾回收。
4. 工具具有不可逆外部副作用时，引入幂等键、执行租约或事务性 outbox，而不能只依赖 ToolResult checkpoint。
5. 多 Agent 并发写入同一 run 时，引入线程安全、进程安全和分布式 sequence 分配。
6. Replay 需要证明完整因果关系时，实现 Started/Finished 配对和事件状态机校验。
