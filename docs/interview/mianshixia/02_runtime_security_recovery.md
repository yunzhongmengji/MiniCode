# MiniCode：工具执行、安全权限与状态恢复

资料性质：简历完成版模拟练习参考设计，不能作为未经核验的个人实绩证明。

## 问题：MiniCode 的结构化 Tool Calling 怎样实现？

检索词：Tool Calling、Function Calling、ToolCall、ToolResult、call_id、工具定义。

主回答：把工具名称、描述和参数 Schema 提供给模型，模型只返回候选调用。适配器解析协议，Dispatcher 查找注册工具、验证参数、评估策略并请求必要审批，工具执行后用相同 call_id 返回结果。模型下一轮通过这些结果继续决策。

关键边界：模型响应解析、Pydantic 参数校验、路径语义检查、权限判断是不同层。JSON 合法不代表参数正确，更不代表获准执行。

## 问题：为什么要使用工具注册表和白名单？

检索词：Registry、Dispatcher、白名单、未知工具、默认拒绝。

主回答：注册表限定程序实际提供的能力，模型不能通过编造工具名调用任意函数。工具策略默认拒绝未配置能力；显式列出的读取类操作可以允许，有副作用的操作要求审批或拒绝。注册能力、向模型展示定义、批准某次执行是三个不同动作。

验证：请求未知工具、重复注册、未配置策略和伪造名字时，程序应明确拒绝且不产生副作用。

## 问题：Pydantic 的 strict、extra forbid、frozen 分别做什么？

检索词：Pydantic、Schema、strict、frozen、extra forbid、参数校验。

主回答：strict 限制宽松类型转换，extra forbid 拒绝未定义字段，frozen 限制普通赋值修改。它们固定工具输入合同，但不证明路径在工作区内、替换文本唯一或用户已批准；这些还需要策略和工具内部校验。

例子：字符串路径能通过类型检查，却仍可能越界；编辑参数字段齐全，也可能找不到唯一的旧文本。

## 问题：AI 风险分级和程序权限策略谁说了算？

检索词：AI 风险判断、风险分级、Policy、ALLOW、ASK、DENY、审批。

主回答：完成版采用确定性策略作为底线，按操作种类、影响范围和可逆性分级；AI 风险判断只提供辅助线索，不能单独把硬拒绝放行为允许。读取受控文件可允许，创建和修改需审批，凭据外传、修改策略和未开放操作默认拒绝。工具内部仍复查路径和执行前条件。

取舍：AI 有助于解释复杂风险，但输出不稳定；最终执行约束必须由可信程序控制，模型和 Skill 不能改写策略。

## 问题：用户拒绝编辑后，MiniCode 怎样处理？

检索词：审批拒绝、用户拒绝、ToolResult、is_error、工具预算。

主回答：不执行编辑，返回与调用 ID 对应的拒绝结果，历史保留调用和拒绝证据，模型可以停止、解释或改选允许的动作。拒绝并不必然结束整个任务。

计数口径：Runtime 正常返回拒绝或校验错误也算一次调用尝试，避免反复失败绕过预算；实际成功执行次数另行统计。执行过程抛出意外异常则进入异常路径，不能假装收到成功结果。

## 问题：Skill 告诉模型“无需审批”，能绕过编辑权限吗？

检索词：Skill 越权、提示词、审批绕过、权限继承。

主回答：不能。Skill 只影响模型提出什么请求，Dispatcher 仍按可信策略检查。模型就算直接返回 edit_file，也需要通过 ASK 审批；正文不能自行提高权限。

验证：用脚本模型固定提出编辑调用，加载要求跳过审批的 Skill，让审批者拒绝。检查实际发生审批、文件未变、拒绝结果与 call_id 正确对应。真实模型可能不提出编辑，不能单靠它验证程序分支。

## 问题：怎样防御仓库或工具结果中的 Prompt Injection？

检索词：Prompt Injection、提示注入、README、伪造审批、工具输出、安全审查。

主回答：把仓库、工具结果、Skill 和自动记忆视为可能含有不可信指令的数据，不允许其中“用户已批准”等文字成为授权。执行侧继续限制工具范围、参数和副作用；完成版的内容规则用于标记伪造角色、越权目标与秘密外传等风险，不承诺覆盖所有语义攻击。

验证：恶意 README 要求读密钥、工具结果伪造批准、记忆要求改策略时，检查实际动作与文件副作用，而不是只看模型是否口头拒绝。模型回答和日志的泄漏还需要单独治理。

## 问题：Workspace 是不是安全沙盒？为什么不直接把 cwd 指向项目目录？

检索词：Workspace、沙盒、sandbox、cwd、路径校验、open。

主回答：Workspace 校验经过自身方法的文件访问；cwd 只是进程开始运行的目录。测试代码直接调用 open 或创建子进程，不会自动走 Workspace，因此它们不是 OS 级隔离。路径检查、固定 argv、环境白名单和审批能降低风险，但不能代替进程级沙盒。

范围：本知识库不追加“已实现沙盒”的经历。进程隔离是额外设计议题，可讨论容器、默认断网、最小文件暴露、资源限制和整体清理，但不能把方案说成已上线能力。

## 问题：循环如何停止？预算是不是等于准确的账单硬上限？

检索词：max_turns、max_tool_calls、Token 预算、COMPLETED、停止原因。

主回答：模型没有后续工具调用可以正常收尾；达到模型轮次、调用尝试或用量阈值时按不同原因停止，缺 Runtime、异常和取消也区分处理。COMPLETED 只说明循环正常结束，代码是否正确由独立验收判断。

用量边界：累计 Token 通常在响应返回后核对，当前响应可能已跨过阈值，不是严格预付费限额。工具数在执行前检查，不能与费用预算混为一谈。

## 问题：工具超时、取消和错误如何反馈？

检索词：超时、timeout、CancelledError、预期异常、进程树、失败恢复。

主回答：预期工具失败转成带调用 ID 的错误结果，供模型调整；程序意外异常、取消和整任务超时保留各自语义，不能全部吞成成功。限制输出防止内存无限增长，记录失败发生在审批、工具还是模型阶段。

边界：终止直接子进程不等于清理整个后代进程树，超时也不会自动撤销已经写入的文件或外部副作用。

## 问题：Checkpoint 保存什么，resume 与 Replay 有什么区别？

检索词：Checkpoint、resume、Replay、历史、预算、快照。

主回答：Checkpoint 保存同一个 Run 的对话和工具状态、进度计数与运行内知识快照，用于继续中断任务；resume 保留原运行身份和已用预算，根据调用与结果匹配识别 pending。完成版中 Skill 与 Memory 使用原快照，不在恢复时悄悄更换参考。

Replay 是读取 Event 顺序复盘过程，不再执行工具。Event、Artifact 和 Checkpoint 分别服务于过程、输出和恢复，不能把只读回放叫成重新运行。

实现标记：Memory 快照是完成版方案的一部分，不从现有 Skill 字段反推当前已接入记忆。

## 问题：Checkpoint 能保证工具只执行一次吗？

检索词：幂等、exactly once、副作用、崩溃窗口、原子性、重复编辑。

主回答：不能。工具修改成功后、Checkpoint 保存前崩溃，磁盘效果和恢复状态可能不一致。仅记录执行前 pending 也分不清“还没执行”和“已经执行但没记结果”。需要按动作使用幂等键、执行前条件或事务，而不是靠一个状态标志消除不确定性。

例子：精确替换成功后旧文本消失，再执行可能报不匹配；这有助于避免盲目重复替换，但不是已实现成功去重或恰好一次保证。

## 问题：日志、Event、Artifact 与审计是否等价？

检索词：Event、Trace、Artifact、日志、审计、哈希。

主回答：普通日志便于人排查，结构化 Event 便于按 Run、阶段和调用关联；Artifact 保存较大输出，事件保留引用；Trace 是可导出的过程记录。审计还需要访问控制、保留策略和完整性治理，不能仅有内存事件就声称持久不可篡改审计。

哈希用于确认关联文件内容未变化，不是身份鉴权，也不证明工具输出真实或任务结论正确。
