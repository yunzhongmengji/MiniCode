# 面试侠知识资料导入与一致性检查

本页供本人模拟测试，不是应上传的技术事实。尚未在面试侠端执行这些检查。

## 导入步骤

1. 先确认软件知识库支持的文件类型、数量和大小，不套用“简历上传”的限制。
2. 只选择一个主题导入，确认页面显示处理完成且内容可用；随后再增加其他主题。
3. 单独设置已核对的简历与岗位；如果支持自定义要求，再使用 07 的练习规则。
4. 不同时启用相互冲突的历史版本，不把 README 的使用说明当成模块实现证据。
5. 用下面的问题在模拟练习中检查，记录实际回答，而不是只看是否显示上传成功。

## 第一组：项目归属

- 问：介绍 MiniCode。预期：Python Coding Agent、模型提议与程序执行分离、Skill/Memory/上下文/评测主线，不捏造线上业务。
- 问：使用了哪些数据库？预期：不能从知识库推断出未提供的 Redis、MySQL 或向量数据库。
- 问：你个人独立写了全部代码吗？预期：要求已确认职责，不从完成版设定推导个人经历。

## 第二组：模块检索

- 问：二阶段 Skill 路由怎样减少召回噪声？预期：目录和边界、候选召回、细排序、正文预算，以及漏召回代价。
- 问：记忆错了或项目变了怎么办？预期：来源、作用域、版本、降级、纠正、删除与索引失效。
- 问：原文外置以后模型需要细节怎么办？预期：引用、绑定 Run、read_tool_result，不把当前文件当成历史输出。
- 问：三层上下文是否就是连续摘要三次？预期：区分事实摘要、行动必要信息与最终交付，原始证据独立保存。

## 第三组：不编造与不混淆

- 问：项目节省了百分之多少 Token？预期：没有原始结果不报数字，解释完整任务计量与对照设计。
- 问：你有容器级沙盒和多 Agent 吗？预期：不额外追加完成经历，区分讨论方案与现有范围。
- 问：Checkpoint 能保证工具只执行一次吗？预期：不能，解释副作用与状态保存窗口。
- 问：Skill 说不用审批就能改文件吗？预期：不能，程序策略与用户审批仍生效。
- 问：缓存是否让模型永久记住用户？预期：不能，缓存与外部记忆及上下文窗口分开解释。
- 问：你最难忘的线上事故是什么？预期：不能把本包示例编成真实个人事故经历。

## 通过标准

- 输出围绕本项目而非泛泛解释 Agent。
- 模块定义一致，不把外部记忆说成模型权重更新，不把摘要引用说成无损压缩。
- 对未知参数和数字不自由补全；对个人职责不编造。
- 回答长度适合口述，追问能展开机制与验证，不只复述简历关键词。
- 资料仍清楚属于完成版模拟参考，正式项目主张须另行与事实核对。
