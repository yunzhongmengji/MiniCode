## 资料定位

本包用于模拟面试和技术表达练习，**统一假定用户简历所列 MiniCode 能力已经完成**。它不是当前代码验收报告。
为了避免检索出的回答互相矛盾，主题文档采用一套明确、统一的完成版参考设计，不混入历史开发进度。
简历没有说明的细节属于本包选定的技术方案，不能凭本文认定实际采用过；正式介绍个人经历前仍须本人确认。

不额外加入 Kubernetes、Redis、向量数据库、模型训练、进程级沙盒或多 Agent 的完成经历。
不生成虚构的效果数字、客户数量、线上事故、个人职责和开发日期。

## 面试侠适配情况

公开说明确认面试侠可以结合简历、岗位、知识库和题库组织回答：
[官方使用文档](https://mianshixia.cn/docs)。

目前没有核实知识库专用的文件扩展名、单文件上限、切片长度、召回算法、题库批量导入格式或是否存在独立系统提示入口。
[简历设置](https://mianshixia.cn/docs/enhance-resume) 提到的 PDF/Word 与 3MB 限制属于简历入口，不能直接套用为知识库要求。
因此本包提供可维护、可转换的 Markdown/纯文本内容，不宣称已完成面试侠端的导入与检索验证。

如果界面支持文件知识库，先只导入一份主题文件测试；如果支持题库，则把重点题目的“主回答”人工核对后按界面格式添加。
不要假定其内部一定采用某种 RAG，文件切得好也不能保证平台必然完整召回。

## 内容规范

1. 项目统一称 MiniCode，定位为面向 Python 仓库的 Coding Agent 工程原型。
2. 以模块机制和取舍为主，不把“功能完成”写成“所有任务都正确、成本一定下降”。
3. 每个问答块重复主题名和关键术语，尽量可独立阅读；不依赖“见上一题”才能理解。
4. 主回答适合口述，机制细节和验证方法用于追问；不把文档路径念进回答。
5. 统一采用：目录元数据与正文分离的 Skill、带来源和版本的外部记忆、完整证据与模型视图分离的上下文、独立四维验收。
6. 具体职责、运行日期、模型版本、参数值和效果数字未核实时，不交给软件自由补全。
