# MiniCode：自动化记忆沉淀、跨任务复用与纠错

资料性质：以简历全部完成为前提的模拟面试参考设计。本文件统一说明完整 Memory 方案，不作为当前源码或个人贡献证明。

## 问题：MiniCode 的 Memory 不是已经保存了聊天记录吗？

检索词：Memory、长期记忆、聊天历史、Checkpoint、Skill、跨会话。

主回答：聊天历史记录同一个 Run 发生了什么，Checkpoint 用于继续这个 Run；Memory 是筛选后可跨独立任务复用的项目事实、经验或明确偏好。Skill 主要保存方法。新任务不应该自动继承全部旧对话，而应只读取有来源、在当前范围仍适用的少量知识。

例子：某测试路径适用于某类任务是项目事实；定位测试失败的方法是 Skill；已执行到哪一步是 Checkpoint。它们可以关联但不能互相替代。

## 问题：自动记忆的“执行—反思—提炼—分级存储—索引更新—按需复用”怎样工作？

检索词：自动提炼、反思、记忆闭环、经验沉淀、索引更新。

主回答：执行先产生真实工具结果与验收信息；反思提出可复用候选；提炼把一次性日志整理成有限事实或带前提的方法。程序校验候选类型、来源和作用域，根据风险决定采纳或人工确认，然后存储并更新索引。新任务检索前检查有效性，复用后的新证据用于修正、降级或删除。

自动化是流程自动衔接，不意味着模型拥有直接写入全部长期记忆的权限，也不代表每个候选都应采纳。

## 问题：一次工具成功就能沉淀成可靠经验吗？

检索词：来源校验、事实正确性、泛化、成功经验、Ground Truth。

主回答：只能支持有限结论。例如 run_tests 成功说明该目标当时完成了执行，不能说明它覆盖所有修改，也不能保证以后仍通过。记忆必须保留适用条件，并区分直接观察、解释与行动建议。

来源真实性和结论支持程度分开检查：文本确实出现在工具输出里，不等于它能支持候选记忆。模型最终说“测试通过”也不能替代真实工具证据。

## 问题：完成版怎样从执行结果中提炼记忆？

检索词：LLM 提炼、结构化候选、Schema、反思模型、采纳。

主回答：完成版让提炼过程只读取受限的任务与执行证据，输出符合 Schema 的候选，包含事实、条件、来源和不确定项；不接受任意指令升级成长期事实。宿主校验 source Run/call、工具参数、结果状态和必要的证据片段。

提炼可以使用模型，但写入与采纳由程序控制。项目观察可先保守采纳，用户偏好必须有明确用户表达，高风险或冲突内容进入人工确认。不能把输出 JSON 中的 approved=true 当作真实批准。

## 问题：记忆记录保存什么？使用什么存储？

检索词：MemoryRecord、schema、JSON、项目隔离、证据、版本。

主回答：完成版参考合同保存 ID、类型、规范内容、项目或用户作用域、适用条件、来源 Run/call、最小证据、版本状态、依赖指纹及采纳依据。小规模采用宿主状态目录中的版本化记录和轻量索引，不为了“长期记忆”强行引入向量数据库。

证据必须可跨进程核对；只存一个内存 Artifact ID 或 hash，下一次运行可能无法还原。哈希支持一致性比较，不证明事实正确。

## 问题：分级存储与项目隔离怎样定义？

检索词：分级存储、scope、用户偏好、项目事实、私有记忆、候选。

主回答：区分临时候选、已采纳项目事实、明确用户偏好和审核后的方法知识。候选有较短生命周期，不直接进入后续任务；项目事实限定仓库；偏好限定用户且可撤回；方法提升到 Skill 还要单独发布。

检索之前先过滤权限、项目、状态和版本，再计算相关性。不把其他项目的经验或某用户偏好放进公共目录后再让模型自行判断是否能用。

## 问题：Memory 索引更新和按需检索怎么做？

检索词：索引、检索、关键词、语义、版本失效、Top-K。

主回答：完成版小规模方案在采纳、纠正和删除时同步更新类型、作用域、状态、标签和词项索引。新任务先过滤有效记录，再根据任务类别和内容匹配选少量结果，控制注入预算。简单索引即可支撑最小闭环，语义召回是可替换能力，不是必选依赖。

一致性：记录版本与索引版本需要可核对；更新失败的记录不能仍通过旧索引被当作有效记忆。单机原子更新与多进程并发写入是不同问题，不能自动声称分布式一致性。

## 问题：Memory 怎么进入模型？会不会覆盖用户要求？

检索词：记忆注入、低信任参考、instructions、message_history、模型输入。

主回答：通过校验的记忆作为明确标记的历史参考进入请求视图，保留来源和适用条件，不伪造成本次真实工具结果，也不提升成能够覆盖用户指令的系统政策。当前任务的明确要求和新证据优先于旧参考。

完成版一次运行固定参考快照，恢复时延续原版本；强制撤回或失效需要显式处理，不能中途悄悄换内容。模型使用历史测试入口时仍需本次审批与执行，过去通过不等于本次通过。

## 问题：错误、陈旧和冲突记忆怎样纠正？

检索词：记忆污染、遗忘、过期、删除、冲突、版本、用户纠正。

主回答：先按作用域和规范事实键识别重复，比较是补充、冲突还是替换。冲突保留来源与版本，不能只按最新时间决定真相；来源失效、目标消失或已监控条件变化时降级或停止注入。用户纠正和删除后，更新记录状态、索引与相关缓存，避免旧版本继续出现。

边界：监控文件未变化不保证环境和未监控依赖都不变；TTL 或置信分数也不能代替证据复核。

## 问题：怎样复用修复经验，而不是记住某一道题的答案？

检索词：错误修复加速、经验泛化、数据泄漏、任务复用。

主回答：保存故障特征、定位依据、适用条件、有效修复方法和验证方式，而不是照搬某次 patch。后续先检查任务是否满足条件，把旧方法当候选路径，用本次文件和测试重新验证。

验证：提炼与测试任务分开，加入名称相似但根因不同、旧经验已经过期和项目不匹配的反例。不能把见过的同一道题再次跑通称为跨任务泛化或证明加速。

## 问题：Memory 怎样提升成 Skill？是不是自我训练？

检索词：Skill 生长、经验提升、自动学习、RL、模型权重、受控发布。

主回答：完成版从多次有证据的经验中形成候选方法，检查通用性、冲突、重复功能和隐私，再用独立任务评测，经受控确认发布为 Skill 新版本，保留回滚。它更新外部知识和方法，不改变基础模型权重，不自动等于 RL。

发布边界：不把某个用户偏好、某项目密钥或一次模型猜测提升成公共 Skill；模型也不能自行更改权限策略与验收规则。

## 问题：怎样证明 Memory 带来收益？

检索词：Memory 评测、跨会话对照、错误记忆、污染反例、成本。

主回答：固定任务、模型、Skill、预算及代码版本，只改变 Memory 开关，并把已有经验任务和未见任务分开。检查独立验收、探索调用、完整用量和时延，同时加入错误、过期、跨项目和删除记录，验证系统会拒绝不合格参考。

收益口径：成功复用一次说明链路可用，不证明总体成功率或成本改善。没有可核对的记录，不给出“加速多少”或“自动学习效果”的数字。
