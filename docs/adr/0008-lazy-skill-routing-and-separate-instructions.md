# ADR-0008：使用轻量 Skill 路由、延迟加载与独立模型指令

- 状态：接受
- 日期：2026-09-09

## 背景

Coding Agent 需要按任务加载可复用的方法说明。如果把所有 Skill 正文永久放进 Prompt，会浪费上下文、增加指令冲突，并扩大不可信内容的暴露面。若把 Skill 直接写入对话历史，又会混淆用户消息、工具事实和运行期指导。

系统还需要能够离线测量路由质量，并在不改动 QueryLoop 的前提下替换召回或排序算法。

## 决策

1. 使用 `manifest.json` 保存名称、描述、入口和标签，完整方法保存在独立 `SKILL.md`。
2. 启动发现阶段只读取 Manifest；收到任务后执行召回、排序和数量截断，再延迟加载选中的正文。
3. 每个入口文件相对于其 Skill 目录解析，并受 Workspace 和 byte 上限约束。
4. QueryLoop 使用最近的用户消息选择 Skill，一次运行只构建一次 SkillContext，后续模型轮次复用。
5. Skill 文本写入 `ModelRequest.instructions`，不加入结构化 `conversation`。
6. 选择和加载产生结构化事件；加载失败或取消在记录后保持原有控制流。
7. 使用带正例和负例的 `SkillRoutingCase` 数据集计算精确匹配率，并保留具体失败结果。
8. Skill 只能指导模型，不能绕过 ToolDispatcher、Policy、Approval 或 Workspace 边界。

## 备选方案

### 每次加载全部 Skill

实现简单，但上下文成本随 Skill 数量增长，并使无关或恶意指令进入每次请求。

### 将 Skill 写入对话历史

可以复用现有消息格式，但会污染真实任务记录，使恢复、回放和 Provider 转换难以区分事实与附加指导。

### 直接使用 Embedding 或模型路由

语义能力更强，但引入索引、模型成本和非确定性。当前先建立可复现的关键词基线和评估接口，再用数据决定是否替换。

## 后果

正面后果：

- 未选中的正文不消耗 Token，也不会被读取。
- 对话历史保持 Provider 无关的真实结构。
- 召回、排序、加载和编排可以独立替换与测试。
- 事件能够解释模型调用前选择并加载了什么。
- 固定评估集可以发现漏选和误选回归。

负面后果：

- 当前关键词算法无法理解同义词或跨语言语义。
- 文件发现、路由和加载增加了组件数量及错误边界。
- 本地 Skill 内容仍可能包含 Prompt Injection，必须继续视为不可信输入。
- byte 上限不能精确等同于模型 Token 预算。

## 重新评估条件

- 固定路由评估集显示关键词准确率不足。
- Skill 数量增长到文件扫描或内存 Catalog 成为瓶颈。
- 需要远程 Skill、签名分发、版本选择或持久缓存。
- 上下文预算要求按 Token 精确分配多份 Skill。
